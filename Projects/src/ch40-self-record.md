```bash
读毛泽东选集的实践论与矛盾论
实践论篇:
    通过实践而发现真理，又通过实践而证实真理和发展真理。从感性认识而能动地发展到理性认识，又从理性认识而能动地指导革命实践，改造主观世界和客观世界。实践，认识，再实践，再认识，这种形式，循环往复以至无穷，而实践和认识之每一循环的内容，都比较地到了高一级的程序。这就是辨证唯物论的全部认识论，这就是辨证唯物论的知行统一观。
    
矛盾论篇:
    立意?
        事物的矛盾法则，即对立统一的法则，是唯物辩证法的最根本的法则。辩证法是研究对象本质自身的矛盾。研究这个法则时涉及许多的哲学问题:[两种宇宙观，矛盾的普遍性，矛盾的特殊性，主要的矛盾和主要的矛盾方面，矛盾诸方面的同一性和斗争性，对抗在矛盾中的地位]

可错论:
    1. 放弃了寻找某种"最终完成"的确定性，转而研究知识如何在不确定，有局限，且必然社会化的条件下被暂时性地生产与修正。
    2. 主张是人类无法绝对肯定任何知识，所有知识宣称在原则上都可能存在错误。知识系统的健康且kk依赖于承认自己"可能出错"，并据此建立持续的误差修正机制。

检验论:
    1. 如果知识永远是暂时的，那么"检验"就不是去寻找证实,而是设计更有效的证伪与误差控制程序。
    统计推断范式贝叶斯因子:
        1. 主观贝叶斯主义允许基于个人背景知识设定先验，客观贝叶斯主义则寻求"无差别原则"等规范来约束先验，以平衡灵活性与客观性。
        2. 检验论的核心张力: 如何在利用背景知识的同时，避免它变成偏见。
    在因果推断的认识论分层:
        1. 随机对照试验特殊性在于认识论的性质，从而创造一种无需知晓所有混杂因素即可进行推断的认知条件。
        2. 无法随机化的场景: 工具变量，断点回归，双重差分等标准实验方法，其有效性高度依赖于一系列不可直接检验的假设，要求研究这进行更精细的敏感性分析和证伪努力。
    可重复性危机与制度性纠错:
        1. 心理学的可重复性危机暴露了可疑研究操作的系统性风险，应对主要制度性纠错，而非个人德性
        2. 预注册强制研究者在数据收集前公开假设，方法和分析计划，防止事后篡改。
        3. 开放数据与代码则允许独立验证。

    2. 从个体认知到制度性认识论
        知识的生产与检验本质上是社会性的，依赖于分工，信任网络和制度设计。
        社会认识论研究集体如何产生，分配和验证知识。证言知识关注我们为何以及何时应当接受他人的话作为知识。
        认识不公正分为证言不公正(因为说话者身份而系统性贬低其可信度)和解释学不公正(集体解释资源的缺失使某些群体的体验无法被理解。) 认知权利与伦理政治权力是交织的，偏见不仅是个人态度，更是结构性问题。
        同行评审作为科学知识的核心把关机制，其认识论功能也受到审视。研究指出，评审人存在主观性与偏见，其决策的问责性与合理性仍需加强。将同行评审理解为一种制度化的可错程序，并非真理的裁决者，有助于更诚实地评估其作用于局限。

认知论与检验论: 
    一种过程性，概率化，社会化的知识观。不再关注"知识是否绝对确定"，而是关注"在给定的认知与制度条件下，我们如何系统地降低犯错的风险，并更快地发现和修正错误"
    "完成"是一个危险的幻觉。更稳健的立场是将任何理论和政策都视为暂时有效的假设，其有效性依赖于持续的可证伪性压力，透明的证据积累，以及能够暴露偏见的社会性审查机制。知识的权威性，最终来自它[可被修正的开放性, 证据标准，可靠性，稳定性，权利制衡(责任归属)]。
```

### 0916
```bash
寻找出路: 现在想不出来，是因为看的太多，想的太远，反而看不到眼前哪一步.
1. 承认你现在的位置
    a. 同时在处理3个以上的假设，每个都推演到一半
    b. 你开始怀疑自己之前的每一步改动
    c. 你盯着代码看，但看不出哪一步是对的，哪一步是错的
    这不是能力问题，这是认知过载，解决办法不是"再想清楚一点"，而是把问题切到小得不能再小
2. 只做一件事情-确认失败点
    在copyinstr2失败的那一行，打印出copyinstr被调用时的srcva, max, p->sz, 以及它实际返回的值。
    就做这一件事情。不要顺手改权限，顺手看exec, 又顺手查页表。
    你会得到一组数字，这组数字会告诉你:
        是srcva + i < p->sz这个条件没有生效?
        还是p->sz本身就是错误的?
        还是copyinstr根本没有调到?
    一次只验证一种假设,失去观察能力，就是因为你同时在验证多种假设。有因必有果，抓住不变量来分析变量等原因。每次都只改变一个因素。
3. 把死胡同画出来
    用drawio, 画出框 [用户进程] --exec--> [内核copyinstr] --读--> [用户内存]
    然后再这个箭头上写: 这一步我亲眼验证过吗?
        a. exec 有没有真的把BIG传进去? -- 打印长度参数
        b. copyinstr 有没有真的被调用? -- 加一行 printf。
        c. 读到的内存是不是BIG的内容? -- 打印前几个字节。
    你会发现，至少有一个箭头你没有亲眼看过,只是"推理"它应该是对的。那个箭头就是出口。
4. 允许自己"退回去"
    死胡同最典型的特征: 你不敢退。你觉得退了就白干了。
    但真相是: 你现在卡住了，恰恰是因为你站在一个你其实没有验证过的地基上，往上盖了三层。退回去不是浪费。是把地基重新踩实。具体动作:
        1. 把你最近改的copyin / copyout / copyinstr 全部git stash 或注释掉。
        2. 跑一次 copyinstr2. 它应该过。
        3. 然后依次只恢复一个改动，再跑一次。
        4. 哪一次从"过"变成"挂"，那一次就是凶手。
    这是最笨，最慢，但唯一能让你重新看见的方法。你现在需要的不是聪明，是笨。
5. 关于观察能力本身
    你说失去了观察能力，我给你一个具体的，可操作的观察练习:
    在copyinstr2挂掉那一刻，不要想"为什么"，只想"是什么"。
        a. 挂掉的返回值是什么? (exec返回0还是-1?)
        b. 期望是什么?
        c. 实际的p->sz是多少? BIG的长度是多少?
        d. 差在哪一个数字上?
    只描述，不解释。描述到你能用一句话说出，"实际是X, 期望是Y, X和Y差在Z"
    问题已经被压缩成一个具体的，可操作的差异
```
